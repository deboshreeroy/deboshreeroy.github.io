Goodreads Book Recommendation System

Built and evaluated a personalized recommender using Goodreads interactions, comparing popularity baselines to collaborative filtering and measuring performance with offline ranking metrics.

machine learning recommenders ranking evaluation
← back to selected work

Overview

Personalization is only as good as its evaluation. This case study emphasizes tradeoffs and measurement.

Problem

Recommend books a user is likely to enjoy. The goal isn’t just “accuracy,” but better ranking and coverage: surfacing relevant items early while avoiding popularity traps.

  • How does personalization compare to “most popular”?
  • What do offline metrics say about ranking quality?
  • Where does collaborative filtering break down?

Data

Goodreads public datasets (user-book interactions / ratings / shelves), filtered to active users and books.

  • Train/validation/test split by time (preferred) or holdout
  • Implicit feedback conversion (e.g., rating >= 4 = positive)
  • Sparsity handling and cold-start notes
Figure: Offline evaluation summary (placeholder — add your plot/table screenshot).

Models

  • Baseline: popularity ranking (global + genre bucket)
  • CF: user-user or item-item collaborative filtering
  • Optional stretch: matrix factorization / ALS

Evaluation

  • NDCG@K (ranking quality)
  • Precision@K / Recall@K (top-K relevance)
  • Coverage + novelty (product-friendly metrics)

Key takeaways

  • Personalization improves ranking for active users with history
  • Popularity baseline is hard to beat for cold-start users
  • Offline improvements may not translate without online tests

Where it breaks

  • New users / new books (cold-start)
  • Popularity bias reduces diversity
  • Sparsity causes unstable neighbors/factors

Next steps

  • Add content features (genres, embeddings from descriptions)
  • Hybrid ranker + explore/exploit strategy
  • Define online experiment + guardrails (CTR, long-term retention)
