Mental Health Predictions from Wearable Signals

Built a prediction pipeline using wearable + survey features to model mental health outcomes, with emphasis on evaluation, calibration, and interpretability.

Overview

A full ML case study framed like a product problem: define the outcome, build a reliable model, and report tradeoffs.

Problem

Predicting mental health outcomes is a high-signal, high-noise problem: measurements are incomplete, labels can be subjective, and errors aren’t symmetric. The goal was to build an interpretable baseline that is honest about uncertainty and generalization.

  • What signals are most predictive (sleep, activity, heart rate variability, routine)?
  • How stable are predictions across individuals and time?
  • How should we evaluate performance for a risk-scoring use case?

Data

Wearable time-series summaries + survey/clinical labels. Features include daily aggregates and rolling-window behavior.

  • Inputs: sleep, steps/activity, heart metrics, routine consistency
  • Targets: stress / depression / mental wellbeing proxy label (binary or ordinal)
  • Split: subject-aware split (avoid leakage across the same person)

Approach

  • Feature engineering: rolling averages, variability, weekday/weekend patterns
  • Baselines: logistic regression / tree-based model (e.g., XGBoost)
  • Handling imbalance: class weights + threshold tuning
  • Calibration: reliability curve + calibrated probabilities
  • Interpretability: coefficients / SHAP to explain drivers

Evaluation

  • Primary: AUROC / AUPRC (depending on imbalance)
  • Decision-focused: precision/recall at operating thresholds
  • Calibration: Brier score / reliability plots
  • Generalization: per-subject breakdown + error analysis

Key findings

  • Sleep consistency and routine stability were strong predictors (more than raw volume metrics)
  • Model confidence varied substantially across individuals → calibration mattered
  • Error analysis revealed specific subgroups where signals were noisier (missingness, irregular schedules)

Where it breaks

  • Missing/irregular wearable data produces unstable window features
  • Labels may not reflect real-time state (survey lag, subjectivity)
  • Population shift: model trained on one cohort may not generalize

Product framing

If this were a real product, I would treat this as a risk score with careful thresholds and human-in-the-loop support. The most important deliverable is not “accuracy,” but reliable ranking + calibrated uncertainty.

Next steps

  • Temporal modeling (sequence models) with strict leakage controls
  • Personalized baselines per user (deviation-from-self features)
  • Prospective evaluation + fairness review across subgroups
