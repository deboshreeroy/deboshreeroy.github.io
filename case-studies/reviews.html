Mining Product Feedback for Friction Signals

Applied NLP to turn unstructured review text into structured themes, sentiment trends, and prioritizable product signals.

nlp embeddings clustering sentiment
← back to selected work

Overview

This is an “insights” project: the output is a decision-ready summary, not just a model.

Problem

Product feedback is abundant but messy. The goal was to extract stable themes (feature requests, pain points, performance issues) and track how they change over time.

  • What are the top recurring friction points?
  • Which issues are increasing over time?
  • How do themes differ across user segments?

Data

Public review dataset (e.g., app store reviews or Goodreads reviews) including text, rating, and timestamp.

  • Text cleaning + deduplication
  • Time buckets for trend analysis
  • Optional segmentation by rating / device / version
Figure: Theme clusters + sentiment trend (placeholder — add your plot screenshot here).

Approach

  • Sentence embeddings (e.g., SBERT)
  • Clustering (HDBSCAN or KMeans) to form themes
  • Theme labeling (top keywords + representative samples)
  • Sentiment + rating alignment per theme
  • Trend detection across time windows

Outputs

  • Top themes with example quotes
  • Theme prevalence over time
  • “Severity” proxy (low ratings + high frequency)
  • Prioritized backlog recommendations

Key findings

  • Top friction themes (e.g., performance, search, onboarding)
  • Emerging theme that rose after a version change
  • Mismatch: sentiment vs rating in certain clusters

Recommendations

  • Prioritize themes with high severity + rising trend
  • Write experiment ideas for top 2 themes
  • Add telemetry to validate the text signals in-product
